## Multi configuration search ranking evaluation

Evaluate search ranking quality across Reciprocal Rank Fusion (RRF) configurations using query datasets. This tool runs structured queries generated by an LLM against the Pan‑Finder PostgreSQL database, aggregates scores, and produces CSVs and plots for analysis.

### What it does
- Parses each dataset in `queries/` and, for every query, asks an LLM to extract search parameters (intention, keywords, filters).
- Builds a SQL query with `SearchQueryBuilder` and executes it against the database.
- Computes a simple relevance score from the target DOI position per query, aggregates per dataset and per test.
- Saves results to `results/` and generates plots (per‑dataset averages, score distributions, and overall trends).

## Configuration
Create a `.env` file in `benchmark/` (the provided `run.sh` sources this file).

Optional: adjust RRF parameters in `rrf_score_k_values_matrix.json`. Each object is a test configuration with:

- `test_name`: label for the configuration
- `rrf_k_similarity`, `rrf_k_chunk`, `rrf_k_full_match`, `rrf_k_partial_match`, `rrf_k_keyword`: RRF k values

The LLM system prompt is at `prompts/gpt-4.1-mini/1_0_7.md` by default.

## Datasets
Each file in `queries/` contains an array of documents. Every document has a target DOI and a list of queries:

```json
[
	{
		"doi": "10.1234/example",
		"queries": [
			{ "query": "Find experiments on X with Y", "min_position": 0 },
			{ "query": "Datasets about ...", "min_position": 3 }
		]
	}
]
```

`min_position` gives full credit if the target DOI ranks above or at that index; beyond it, score decays linearly over 20 ranks down to 0.

## Dependencies
- Source of truth: `pyproject.toml` (runtime deps + dev extras). Pinned installs are generated `requirements*.txt`.
- Create a venv and install pinned deps:
	```bash
	python -m venv .venv
	source .venv/bin/activate
	pip install -r requirements.txt
	```
- Server code is imported by the benchmark. Install server dependencies:
	```bash
	cd ../server
	python -m venv .venv
	source .venv/bin/activate
	pip install -r requirements.txt
	```

## Quick start

Use the helper script (creates a venv, installs deps, runs the benchmark):

```bash
cd benchmark
./run_hyperparameter_runner.sh
./run_multi_config_evaluator.sh
```

Tip: Ensure the database is reachable (see `DATABASE_URL`) and the model exists at `models/all-MiniLM-L12-v2/` before running.

## Outputs
Artifacts are written to `benchmark/results/`:

- `results_YYYYMMDD_HHMMSS.csv`: per‑dataset average scores for each test configuration
- `average_scores_per_dataset_YYYYMMDD_HHMMSS.png`: bar chart of per‑dataset averages
- `score_distribution_boxplot_YYYYMMDD_HHMMSS.png`: box plot of score distributions per test
- `raw_scores_by_test_config_YYYYMMDD_HHMMSS.json`: raw per‑query scores grouped by test
- `overall_changes.png`: trend of average scores across runs

The LLM response cache is stored at `cache/llm_cache.json`. Delete this file to force fresh LLM calls.

## Customization
- Modify/limit datasets by editing the files in `queries/`.
- Tune RRF parameters in `rrf_score_k_values_matrix.json`.
- Change the prompt or model:
	- Prompt path: `prompts/gpt-4.1-mini/1_0_7.md`
	- Embedding model path: `models/all-MiniLM-L12-v2/`

## Development notes
- The benchmark imports server code via `server/src` package `src.*`.
- Plotting utilities live in `src/plotting.py`.
- Results are deterministic for fixed datasets and cache.

# Extended Benchmarks
In order to run a single benchmark, you should use the following command:
```bash
set -a; source .env; set +a; clear ; .venv/bin/python src/hyperparameter_runner.py -p hyperparameters/hyperparameters-0ab03620-8fd6-11f0-9b02-9b2c06332f10.json
```

where hyperparameters/hyperparameters-0ab03620-8fd6-11f0-9b02-9b2c06332f10.json if the hyperparameters file containing the app settings and the metrics configuration.
